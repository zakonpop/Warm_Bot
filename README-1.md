# Warm Bot

Telegram-бот для прогрева и удержания подписчиков канала. Проверяет статус подписки в реальном времени и ведёт пользователя по цепочке сообщений в зависимости от его поведения.

## Возможности

- Проверка подписки на канал сразу при `/start` (через Telegram API, без кнопок)
- Три сценария (цепочки) сообщений:
  - **Цепочка 1** — пользователь не подписан, серия прогревающих сообщений
  - **Цепочка 2** — пользователь подписан, приветственная/поддерживающая серия
  - **Цепочка 3** — пользователь был подписан, но отписался, win-back серия
- Перепроверка статуса подписки перед **каждой** отправкой сообщения, а не только на границах цепочек — статус пользователя не может "зависнуть" в устаревшем состоянии
- Мгновенное переключение цепочки при live-событии подписки/отписки (`chat_member` апдейт), без ожидания следующего цикла проверки
- Каждое сообщение отправляется ровно один раз
- Гибкая настройка задержек между этапами (в минутах) для каждой цепочки отдельно

## Стек

- Python 3.13
- [aiogram 3](https://docs.aiogram.dev/) — фреймворк для Telegram-ботов
- aiosqlite — асинхронная работа с SQLite
- asyncio — фоновый воркер для отложенных рассылок

## Архитектура

```
warm_bot/
├── main.py           # точка входа, запуск polling + воркера
├── config.py         # токен, id канала, id владельца, имя БД
├── bot_instance.py   # инициализация Bot/Dispatcher/Router
├── database.py       # вся работа с БД (CRUD), без бот-логики
├── subscription.py   # проверка подписки и переключение цепочек
├── handlers.py       # обработчики /start и события подписки
└── scheduler.py      # фоновый цикл рассылки по расписанию
```

Модульная структура специально разделена так, чтобы `database.py` не знал о Telegram, а `handlers.py`/`scheduler.py` не занимались SQL напрямую — это упрощает отладку и позволяет менять логику рассылки, не трогая работу с БД.

## Как это работает

1. Пользователь пишет `/start` → бот проверяет подписку и создаёт запись в БД (если новая), назначает цепочку 1 или 2
2. Фоновый воркер каждые несколько секунд ищет пользователей, которым по расписанию пора получить следующее сообщение цепочки
3. Перед отправкой каждого сообщения воркер заново проверяет статус подписки — если он изменился, пользователь переключается на нужную цепочку
4. При live-событии подписки/отписки от канала бот реагирует сразу же, не дожидаясь очередного цикла воркера

## Настройка контента цепочек

Тексты сообщений и задержки между этапами хранятся в таблице `chains` (SQLite):

| Поле            | Описание                                   |
|-----------------|---------------------------------------------|
| `chain_id`      | номер цепочки (1, 2 или 3)                  |
| `stage`         | номер этапа внутри цепочки (1, 2, 3...)     |
| `delay_minutes` | сколько минут ждать с предыдущего этапа     |
| `text`          | текст сообщения                             |

Заполняется через отдельный скрипт (пример — `seed.py`, в репозитории не хранится, содержит реальные тексты клиента):

```python
import asyncio, aiosqlite
from config import file_name

async def seed():
	async with aiosqlite.connect(file_name) as db:
		data = [
			(1, 1, 0,  "Текст этапа 1 цепочки 1"),
			(1, 2, 60, "Текст этапа 2 цепочки 1 — через 60 минут"),
			# ...
		]
		await db.executemany(
			"INSERT INTO chains (chain_id, stage, delay_minutes, text) VALUES (?, ?, ?, ?)",
			data
		)
		await db.commit()

asyncio.run(seed())
```

## Установка

```bash
pip install aiogram aiosqlite
```

Заполнить `config.py`:

```python
token_bot = "токен от BotFather"
owner_id = 123456789      # твой Telegram ID, для уведомлений об ошибках
chat_id = -1001234567890  # id канала, где проверяется подписка
file_name = "data.db"
```

Бот должен быть добавлен в канал **администратором** — иначе проверка подписки не сработает.

Запуск:

```bash
python main.py
```
